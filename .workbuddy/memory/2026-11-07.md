## 修复 Web 端视频生产 `float division by zero`（11:22 失败任务「11月6日新闻」）
- 现象：`POST /api/tasks` 返回 201 后约 1.4s 任务失败。`models/face2face/log/log.log` 与 `docker logs duix-avatar-gen-video` 的堆栈：`trans_dh_service.py:407 TransDhTask.work → av_utils_ffmpeg.py:162 get_video_info → ZeroDivisionError`。
- 根因：`src-web/app/api/tasks/route.ts` 用 `path.join('/code/data', avatar.videoPath)`，Windows Node 拼出 `\code\data\web\models\xxx.mp4`；Linux 容器内 ffprobe 打不开该文件，帧率/时长解析为 0 触发除零。容器内直接复现：`get_video_info('/code/data/web/models/00885864-...mp4')` → `(30.0, 720, 1280, 10.2)`；反斜杠路径 → `ZeroDivisionError`。
- 修复 1：改用 `path.posix.join` + 反斜杠归一化（并去掉可能已带的 `/code/data/` 前缀），保证提交给容器的是 POSIX 路径。
- 修复 2：合成服务返回的 result 是 `\<code>-r.mp4` 之类的容器相对名，实际文件在 `/code/data/temp/`；`GET /api/tasks` 现在统一映射为 `temp/<文件名>.mp4`，否则 `/api/media` 播放 404。
- 验证：`tsc --noEmit` 通过；短文本任务「路径修复验证」端到端 completed 100%，输出 `models/face2face/temp/f3b4ce78-...-r.mp4`（2.4MB），`/api/media` 200、Range 206 可播放；已手工把该测试任务的 `web_task.output_path` 修正为新格式。
- 旧任务「11月6日新闻」仍是 failed，需重新提交一次；其文本约 300 字，TTS 耗时约 99s，视频合成另需数分钟。

## 修复 `bun dev` 下 better-sqlite3 外部模块 500
- 现象：`bun dev` 启动 Next 16.4.5 (Turbopack) 后 `/api/models`、`/api/tasks` 全 500：`Failed to load external module better-sqlite3-90e2652d1716b047: Cannot find module`。`.next/dev/server/chunks/...js` 中 Turbopack 把 SSR external 写成带 hash 的别名 `require("better-sqlite3-<hash>")`，Bun 1.4.0 解析不了（Next.js issue #86866 / #87737 确认只影响 Bun 运行时）。
- 更深一层：换 `--webpack` 绕开 hash 别名后，Bun 仍报 `'better-sqlite3' is not yet supported in Bun` / `ERR_DLOPEN_FAILED`（oven-sh/bun#4290）。`bun -e "require('better-sqlite3')"` 看似成功只是因为 dlopen 发生在 `new Database()` 时。
- 修复：`src-web/package.json` 的 dev / build / start 脚本改为显式 `node ./node_modules/next/dist/bin/next ...`，让 `bun dev` 只当任务运行器，Next 跑在 Node v22 上，Turbopack 保留。
- 验证：Node+Turbopack（3100）与改后 `bun dev`（3102）均 `/api/health`、`/api/models`、`/api/tasks` 返回 200；Bun+webpack（3101）500。测试残留的 `.next` 备份已从 `models/.cache` 删除。
- 结论：Web 端运行时必须保持 Node；真要用 Bun 运行时需把 better-sqlite3 换成 bun:sqlite，会破坏 Electron/Node 部署，不建议。
